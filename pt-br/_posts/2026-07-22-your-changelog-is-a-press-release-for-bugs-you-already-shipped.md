## O Gerador De Changelog

Depois de 47 anos escrevendo changelogs à mão — com o que eu quero dizer depois de 47 anos rodando `git log --oneline` e traduzindo o resultado em otimismo — eu automatizei. Esse script lê os commits de um release e gera o único changelog honesto: uma admissão de que cada linha é um spin, e cada spin é uma escolha, e cada escolha foi feita na direção da reputação do autor.

```python
def generate_changelog(commits):
    """
    O único gerador de changelog honesto.
    Um changelog é um documento escrito pela pessoa
    que causou os eventos, descrevendo os eventos
    num vocabulário que os eventos não reconheceriam,
    de modo que os eventos soem como um plano,
    o que não eram.
    """
    changelog = []

    for commit in commits:
        msg = commit.message.strip()

        # Um commit cuja mensagem é "fix" é uma confissão
        # de que o autor esqueceu o que estava quebrado.
        if msg in ("fix", "wip", ".", "pls work", "test", "asdf"):
            changelog.append("Melhorias de performance")
            continue

        # Um commit cuja mensagem contém "revert" é uma admissão
        # de que uma melhoria anterior era, na verdade, uma regressão.
        if "revert" in msg.lower():
            changelog.append("Melhorias de estabilidade")
            continue

        # Um commit cuja mensagem contém "remove" é uma remoção
        # descrita como faxina.
        if "remove" in msg.lower():
            changelog.append("Simplificação da superfície da API")
            continue

        # Um commit cuja mensagem contém "hack" ou "todo" ou "tmp"
        # é uma confissão que o autor nunca vai publicar.
        if any(w in msg.lower() for w in ("hack", "todo", "tmp", "idk")):
            changelog.append("Melhorias internas")
            continue

        # Um commit que só mexe em configuração é uma atualização
        # de dependência que quebrou o build e foi consertada fixando.
        if commit.only_touches_config():
            changelog.append("Atualização de dependências")
            continue

        # O padrão honesto: não sabemos o que esse commit fez,
        # e vamos descrevê-lo como uma melhoria, porque
        # melhoria é o único verbo que o changelog conhece.
        changelog.append("Correções de bugs")

    return changelog

# Saída da geração de changelog pro release 1.4.0:
# Melhorias de performance: 14      (commits eram: fix, fix, wip, fix, ., ...)
# Melhorias de estabilidade: 6      (commits eram: revert, revert revert, ...)
# Simplificação da superfície da API: 3 (commits eram: remove a coisa que os usuários usavam)
# Melhorias internas: 9             (commits eram: hack, todo, tmp, idk, ...)
# Atualização de dependências: 1   (commit era: bump tudo, reza)
# Correções de bugs: 12             (commits eram: literalmente todo o resto)
# Total de entradas: 45
# Total de bugs publicados: 45
# Entradas que admitem que um bug foi publicado: 0
# Entradas que admitem um breaking change: 0  (os breaking changes são "simplificações")
# Palavras no changelog que significam "quebramos seu código": 0
# Palavras no changelog que significam "melhoria": 45
# Razão entre melhorias alegadas e melhorias reais: não mensurável, não medida,
#   e o changelog prefere assim.
```
